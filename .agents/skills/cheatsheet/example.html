Power Pattern: Feedback Loop (Highest Leverage)

Give Claude a runnable feedback loop: unit tests, Puppeteer screenshots, iOS simulator output. When Claude can check its own work, 2-3 self-iterations produce near-perfect results. The single highest-leverage pattern.

Power Pattern: Plan First

"Before you write code, make a plan. Ask me for approval first." Claude brainstorms, presents options, waits for OK before touching files. No special tool needed.

Power Pattern: commit push PR

Say "commit push PR". Claude reads git history for commit format, writes the message, pushes the branch, opens the PR. Use gh-axi instead of gh.

Power Pattern: claude -p as Unix Utility

git status | claude -p "summarize what changed and why"
cat error.log | claude -p "what's interesting" --output-format json | jq
Use in CI, incident response, log analysis, any pipeline needing AI reasoning on streamed input.

Power Pattern: Parallel Worktree Sessions

Run multiple Claude sessions in parallel: several git worktrees of the same repo, each in its own tmux pane. Changes don't collide. Use superpowers:using-git-worktrees.

Power Pattern: Codebase Q&A Before Edits

Start unfamiliar codebases with Q&A, not edits. Ask how things work, why decisions were made. Claude explores deeper than grep. Anthropic onboards new engineers 2-3 weeks down to 2-3 days this way.

Trident Cross-Audit

For auth, payments, middleware, migrations, secrets: dispatch code-reviewer + security-reviewer in parallel, cold context. Consensus = fix before merging. Contested = escalate to Opus.

How Claude Works

Context Window
  • Claude reads the full conversation top-to-bottom on every turn. No memory between sessions.
  • Primacy + recency: instructions at the start and end of the window get the most attention.
  • Past ~70% full, performance on complex tasks degrades. Run strategic-compact before hitting this.
  • Each tool call result adds to the window. Parallel tool calls are cheaper (fewer round-trips).
  • Long CLAUDE.md wastes tokens on every turn. Keep it short.
How Claude Reads Requests
  • Infers full output spec from partial requests using task-category defaults.
  • "Write a report" → exec summary + KPIs + table + verdict
  • Ambiguous format → Claude picks one and states the assumption
  • Override by stating the output spec explicitly: "Give me just the function, no explanation."
Thinking Modes
  • Extended thinking (⌥T): internal reasoning up to 31,999 tokens. Best for architecture, complex debugging, multi-constraint problems. Skip for simple lookups and formatting.
  • Verbose thinking (Ctrl+O): shows Claude's chain of thought. Good for auditing whether Claude understood the problem.
  • Overthinking is a failure mode too. Claude stops refining when passes stabilize.
Subagents and Parallel Work
  • Every subagent gets its own context window. Protects main context from lengthy reads/searches.
  • Use for: independent parallel tasks, fresh-perspective code review, long searches, tracer runs.
  • Tracer rule: run one subagent end-to-end before dispatching a fleet. Tracer failure = fix the plan, not the prompts.
Hallucination — When and Why

Next-token predictor. Thin training data = fluent but potentially wrong output.

High-risk triggers — verify before asserting
  • Library API signatures and named exports
  • Exact file paths, line numbers, folder structure
  • Version-specific behavior (Next.js 15 vs 14, Tailwind v3 vs v4)
  • Named functions not read this session
  • Dates, numbers, commit hashes

Mitigations: "Read [file:line] first." / "Quote the file:line backing every claim." / "It's OK to say you don't know." / Run the build/test instead of reasoning about it.

Feedback Loops (Highest Leverage)

The single highest-leverage pattern: give Claude a way to verify its own work.

  • Unit tests: Claude runs the test, sees pass/fail, self-corrects
  • Screenshots (Playwright/Puppeteer): Claude sees rendered UI, adjusts
  • Linter/type-checker output: Claude sees errors, fixes them
  • Build output: Claude sees compile error, resolves it

With a feedback loop, 2-3 self-iterations produce near-perfect results. Without one, Claude declares success based on reasoning alone — unreliable.

Tips

Always run superpowers:verification-before-completion before claiming any fix is done.

Use mp-diagnose for any bug before attempting a fix. Never go straight to editing.

The feedback loop is the highest-leverage pattern. Always give Claude a way to verify its own work.

Use mp-caveman when context is heavy and you just need fast answers — no prose needed.

Invoke skills explicitly by name. Claude won't auto-use them unless triggered or invoked.

Break big tasks into small ones with a verifiable acceptance criterion per step.

Use subagents for work you want a fresh, unbiased perspective on (code review, security audit).
